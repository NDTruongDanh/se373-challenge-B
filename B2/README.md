# B2: Code Mode — answer over many logs without raw logs in context

Implements **Challenge B2** of the _Memory, Context Engineering & Prompt Caching_ module (SE373).

**Goal:** the agent answers a question spanning `logs/app.log` (~2,000 lines),
`logs/test_run.log` (~7,000 lines) and `logs/grep_noise.log` (~1,500 lines),
while raw logs never enter the LLM context — only the aggregated `result` does.

## How Code Mode is implemented

**Write → Run → Receive.** The LLM returns a single tool call `run_code`
carrying a Python program. The runtime executes it; the program calls the
`tools.*` SDK; the model receives only the aggregated `result`:

```python
fails = [l.split("::")[1].split()[0] for l in tools.read_lines("test_run.log", 0, 8000)
         if l.startswith("FAILED")]
result = {"failed_tests": sorted(set(fails)),
          "app_errors": tools.grep_count("app.log", "ERROR auth refresh-token race")}
# ~600KB scanned inside, ~200 chars returned
```

- **Native vs Code Mode:** tools stay the same shape, but the loop
  moves: native = LLM↔tool per file (every raw output lands in context);
  Code Mode = code loops/aggregates inside the runtime, one small return.
- **Runtime:** in-process `exec()` with restricted builtins, denylist
  (`import`/`open`/dunders), path confinement to `logs/`, 5s timeout, and a
  `result` cap (≤2000 chars, ≤50 lines) that forces aggregation — a demo-grade
  sandbox, not a security boundary (documented in `runner.py`).
- **Measure via usage:** `demo.py` prints real `usage_metadata`
  input/output tokens on live runs, plus tiktoken context estimates; the
  scanned-vs-returned counters come from `RAW_STATS` inside the runtime.

## Measured results (offline, deterministic)

| Metric                 | Value                                                                 |
| ---------------------- | --------------------------------------------------------------------- |
| Scanned inside runtime | ~1.6MB / ~31k lines in 6 SDK calls (full-file scans counted honestly) |
| Returned to LLM        | <1KB (558 chars canonical)                                            |
| Reduction              | ~2900x scanned-vs-returned                                            |
| LLM context            | task + result only, ~650 est. tokens (deterministic)                  |
| Answer checks          | failed_tests / app_error_count / grep_count / hint / tried / next ✅  |
| Raw leak               | none (no >50-line message in context) ✅                              |
